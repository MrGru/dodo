# Story E3.8

**Canonical ID:** `e3.8`
**Status:** planned (placeholder)
**Epic:** E3 — API Explorer

## Story

**As a** developer testing an API that requires OAuth 2.0 **I want** it as a fifth auth type
alongside Basic/Bearer/API Key **so that** I don't have to manually fetch and paste a bearer token.

## Acceptance Criteria

- [ ] **AC-1**: `AuthType::OAuth2` renders a real configuration pane instead of `later_step()`.
- [ ] **AC-2**: At minimum, the Authorization Code grant is supported.
- [ ] **AC-3**: A resulting access token flows through the existing Bearer-equivalent send path —
      no new send-pipeline branch.
- [ ] **AC-4**: A refresh token, if present, is stored with the same plain-text-with-notice posture
      as any other secret in this codebase (see ADR-007) — no new, quieter storage path.

## Where it lives (today, as a placeholder)

- `src/api_explorer/services/http/auth.rs`, `src/api_explorer/views/request_auth.rs:163-166`
  (`AuthType::OAuth2 => later_step(...)`), `src/api_explorer/components/later_step.rs`

## Notes

- This is currently the **only remaining caller** of `later_step()` in the codebase — implementing
  it removes that shared placeholder component's last user, which is worth noting when it lands
  (the component itself may then be removable, or kept for the next placeholder).
