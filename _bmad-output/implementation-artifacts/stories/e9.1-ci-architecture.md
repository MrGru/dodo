# Story E9.1

**Canonical ID:** `e9.1`
**Status:** done
**Epic:** E9 — Build, Release & Licensing engineering

## Story

**As a** maintainer **I want** every push checked cheaply and every release checked thoroughly **so
that** iteration stays fast without silently letting release-only breakage through forever.

## Acceptance Criteria

- [x] **AC-1**: `ci.yml` runs `cargo check` per platform plus one debug build on push — no
      `--release` build on push.
- [x] **AC-2**: `fmt` and `clippy` are blocking jobs (`cargo fmt --all`,
      `cargo clippy --all-targets --locked -- -D warnings`), no crate-level `#[allow]`.
- [x] **AC-3**: The four-platform `--release` matrix runs weekly/manual (`release-profile.yml`) and
      on a tag (`release.yml`) — not on every push. The accepted cost (release-only failures
      surface up to a week late) is stated at the top of both workflow files and in
      `docs/release.md`.
- [x] **AC-4**: Two of the four `cargo check` targets (Linux, Windows) cannot run natively from a
      macOS host — documented as an `aws-lc-sys` C-toolchain fact, not a dodo bug; the two Apple
      targets cross-check locally instead.

## Where it lives

- `.github/workflows/ci.yml`, `.github/workflows/release-profile.yml`, `.github/workflows/release.yml`,
  `docs/release.md`
