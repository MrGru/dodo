# Story E6.3

**Canonical ID:** `e6.3`
**Status:** done
**Epic:** E6 — In-app Updater

## Story

**As a** user downloading an update **I want** the archive's integrity checked **so that** a
corrupted or truncated download is caught before install.

## Acceptance Criteria

- [x] **AC-1**: A SHA-256 digest from the same HTTPS origin as the archive is verified before
      install; a mismatch discards the file.
- [x] **AC-2**: This is integrity, not authenticity — `signature` is read, always `null`, verified
      by nothing; this is stated, not hidden.
- [x] **AC-3**: A downloaded file is never executed; extraction runs the system's `tar`.
- [x] **AC-4**: Refusing to install (unwritable install location, read-only volume, bare binary) is
      a success state — "downloaded, install manually" plus the archive's path — not an `Err`.
- [x] **AC-5**: `sha256.rs`/`version.rs` are hand-written (NIST FIPS 180-4 vectors; SemVer §11
      precedence, both exhaustively tested) rather than depending on `sha2`/`semver`, since `sha2`
      is currently only a build dependency.

## Where it lives

- `src/updater/services/verify.rs`, `src/updater/models/{sha256,version}.rs`
