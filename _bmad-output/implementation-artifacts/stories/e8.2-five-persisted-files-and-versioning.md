# Story E8.2

**Canonical ID:** `e8.2`
**Status:** done
**Epic:** E8 — Persistence & `data_dir()`

## Story

**As a** user **I want** dodo's persisted data to survive a version upgrade without corruption or
data loss **so that** my collections, environments, connections, and updater state stay intact.

## Acceptance Criteria

- [x] **AC-1**: Exactly five files persist under `data_dir()`: `collections.json`,
      `environments.json`, `script-consent.json`, `updater.json`, `connections.json`, each behind
      its own trait.
- [x] **AC-2**: `collections.json` copes only with added fields (`#[serde(default)]`); the other
      four carry an explicit `"version"` and refuse a file whose version is higher than known.
- [x] **AC-3**: Persistence and initial load run on the background executor, never the UI thread.
- [x] **AC-4**: `updater.json` is the one exception to "nothing persists across restarts besides
      these five files" — its `skipped_version` would be a lie if it expired every launch.

## Where it lives

- `src/paths.rs` area; each module's own store (`collection_store.rs`, `variable_store.rs`,
  `consent_store.rs`, `updater::services::config_store`, `connection_store.rs`)
