# Epic E9 — Build, Release & Licensing engineering

**Source:** `docs/build-optimization.md`, `docs/release.md`, `.github/workflows/`, `tools/update-manifest/`, `deny.toml`, `THIRD-PARTY-NOTICES.md`
**Stage:** Phase 3 (Solutioning)
**Status:** Done, one question left deliberately open

---

Depends on E0-E8 existing (it packages and releases the whole app); its `update.json` manifest is
what E6's pipeline reads.

| Story | Title | Status | Depends on |
|---|---|---|---|
| **E9.1** | CI: per-platform `cargo check` + one debug build on push; the four-platform `--release` matrix runs weekly/manual/tag-gated only, not on push | Done | E0.1 |
| **E9.2** | `update.json` manifest generated by the standalone `tools/update-manifest` crate (`exclude = ["tools/*"]`, its own `Cargo.lock`), published create-or-update since `gh release create` cannot repair an existing immutable tag | Done | E9.1 |
| **E9.3** | Application icon pipeline: `assets/branding/` master artwork → `scripts/generate-icons.py` → committed `.icns`/`.ico`/hicolor PNGs, kept out of the embedded-asset filters that cover only `icons/**/*.svg` and `themes/**/*.json` | Done | E9.1 |
| **E9.4** | The GPL-3.0-or-later distribution question (via `gpui -> sum_tree -> ztracing -> zlog`) stays explicitly open; `rusqlite`/`sqlx` cannot coexist in the dependency graph; `Cargo.lock` is the only pin on the four git dependencies | **Open question, not a defect** | E9.1 |

**AC (E9.1):** `fmt` and `clippy` are blocking jobs (`cargo fmt --all`,
`cargo clippy --all-targets --locked -- -D warnings`), with no crate-level `#[allow]`.

**AC (E9.2):** Any platform missing from a release manifest fails the whole release — a silently
absent platform would mean those users are never offered an update.

**AC (E9.4, open by design):** `deny.toml` carries no `allow`/`exceptions` entry for the
GPL-3.0-or-later chain, so `cargo deny` keeps surfacing it rather than the question being settled
by omission.
